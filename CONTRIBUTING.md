# Contributing to Brandon Foster's Portfolio

Thank you for your interest in this project!

## The Short Answer: Basically, Please Don't

**Pull requests and external code contributions are not accepted for this repository.**

### Why?
This repository is the personal engineering portfolio, architectural showcase, and interactive resume of **Brandon Foster**. 

Every architectural decision, infrastructure pattern, and line of code—from the scale-to-zero GCP Cloud Run backend, keyless Workload Identity Federation (WIF/OIDC) pipelines, and Terraform configurations, to the React/Vite frontend and MLOps continuous evaluation gates—is intentionally crafted to reflect Brandon's individual technical capabilities, design philosophy, and problem-solving approach.

Accepting external code contributions or pull requests would defeat the purpose of an individual portfolio.

---

## What You Can Do Instead

Even though pull requests are not accepted, community feedback and engagement are very welcome in the following ways:

### 1. Found a Bug or Typo?
If you discover a broken link, visual glitch, or bug while browsing the portfolio, please feel free to [open an Issue](https://github.com/brandocomando/portfolio/issues) describing what you encountered. While pull requests cannot be accepted, verified issues will be reviewed and addressed directly.

### 2. Found a Security Vulnerability?
If you have identified a security vulnerability or sensitive information exposure, please review our [Security Policy](SECURITY.md) and report it responsibly via [GitHub Private Vulnerability Reporting](https://github.com/brandocomando/portfolio/security/advisories) or email to `brandocomando8@gmail.com`. Please **do not** open public issues for security vulnerabilities.

### 3. Looking for Inspiration or Architecture Patterns?
You are welcome to browse the code, learn from the patterns, and fork the repository for your own personal experiments or reference in accordance with the project's license.

If you use any patterns, architectural blueprints, or Terraform modules in your own work, attribution is appreciated!

If you are a recruiter, hiring manager, or fellow engineer wanting to chat about distributed systems, cloud infrastructure, or MLOps:
